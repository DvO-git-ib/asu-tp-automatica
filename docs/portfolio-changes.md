# Технический обзор текущей версии проекта

> Файл сохранен под историческим именем `portfolio-changes.md`, но текущий текст не является журналом изменений. Он описывает фактическую структуру проекта, чтобы репозиторий было легче изучать при просмотре портфолио.

## Назначение проекта

АСУ ТП «Автоматика» — учебный настольный клиент для демонстрации базовых сценариев контроля технологических данных и механизмов разграничения доступа. Предметная область — производство железобетонных конструкций: камеры ТВО, дозаторы, силосы, гидросистема, виброплощадка и другие технологические объекты.

Главная техническая идея проекта — не хранить всю защиту только в интерфейсе. Python отвечает за отображение и пользовательские сценарии, а PostgreSQL дополнительно ограничивает доступ функциями, представлениями, ролями и прикладной политикой.

## Python-часть

### `gui.py`

Основное приложение на Tkinter. Содержит:

- окно авторизации;
- главное окно;
- ролевые вкладки;
- фильтрацию таблиц;
- обновление данных;
- карточки строк;
- экспорт в CSV;
- диалоги изменения параметров, подтверждения аварий и управления пользователями;
- штатную смену пользователя и завершение сеанса.

### `db_connection.py`

Отвечает за PostgreSQL-соединение. Пользователь подключается под собственной ролью БД. Короткий логин `operator` преобразуется в `user_operator`.

### `db_helpers.py`

Единый слой выполнения запросов: `fetch_all`, `fetch_one`, `execute_status_function`, откат транзакции при ошибке и нейтральное сообщение пользователю.

### `auth.py`

Получает логин, ФИО и роль текущего пользователя через `asu_schema.f_get_my_role()`.

### Ролевые модули

- `unprivileged_ops.py` — открытые параметры;
- `operators.py` — параметры оператора и аварии;
- `privileged_ops.py` — полный набор параметров, изменение, журнал и история;
- `admin_ops.py` — пользователи, блокировка, разблокировка и смена пароля;
- `audit_ops.py` — фиксация входа/выхода и журнал сеансов;
- `ib_ops.py` — полный журнал операций;
- `dashboard_ops.py` — сводная панель и матрица доступа.

### `config.py`

Содержит название и версию приложения, размеры окон и параметры подключения, читаемые из переменных окружения.

## Связь Python и БД

Типовой путь операции:

```text
Нажатие кнопки в GUI
        │
        ▼
*_ops.py
        │
        ▼
db_helpers.py
        │
        ▼
параметризованный SELECT функции PostgreSQL
        │
        ▼
check_policy() / серверная логика
        │
        ├── данные
        └── запись аудита
```

Например, изменение параметра проходит:

```text
gui.py
  → privileged_ops.update_parameter()
  → asu_schema.sp_update_parameter(...)
  → check_policy('WRITE', 'PARAMETER')
  → UPDATE control_objects
  → log_access('UPDATE_VALUE', ...)
  → при выходе за границы INSERT alarm_log
```

## Что удобно демонстрировать в портфолио

При показе проекта достаточно нескольких последовательных сценариев:

1. **Непривилегированный пользователь** — видит только открытые параметры.
2. **Оператор** — видит аварии и подтверждает одну из них.
3. **Инженер** — изменяет параметр, после чего изменение появляется в истории.
4. **Инженер** — выводит параметр за допустимый диапазон, что создает аварийную запись.
5. **Администратор ИС** — создает пользователя, блокирует и разблокирует его.
6. **Администратор ИБ** — показывает журнал операций, где видны предыдущие действия.

Эта последовательность хорошо показывает, что роли отличаются не только визуально, а операции связаны с серверной политикой и аудитом.
